Canonical Platform Reference

Per-platform connect and publish flows.

Use this while coding connection setup, capability checks, validation, and composer behavior. Structure: connect path → connected state → create-post path → validation → publish actions.

Instagram

Primary path: Meta OAuth. Fallback: manual token. Relay supported.

post story reel carousel
1

Add channel

Workspace → Channels or Workspace Settings → Social Accounts → Add Channel → Instagram.

2

Choose method

`Connect with Meta` default. `Manual token` advanced. `Relay` fallback.

3

Authorize

User completes Meta flow or pastes app ID, app secret, access token, optional business ID.

4

Verify

Resolve handle, business account, capability set, token health, reconnect risk.

5

Connected state

Show green IG icon, handle, capability badges, last verified, `Manage / Reconnect / Test`.

Create post flow

  • Create Idea → Composer → select `Instagram`.
  • Choose format: `Post`, `Story`, `Reel`, `Carousel`.
  • Upload or pick media from library.
  • Preview in IG-specific mobile frame.
  • Action bar: `Save Draft`, `Send for Approval`, `Schedule`, `Publish Now`.

Validation

  • Aspect ratio and resolution by format.
  • Video length and cover checks for Reels.
  • Safe area checks for Stories.
  • Multi-item ordering and per-slide validation for Carousel.
  • Fail validation before schedule or publish.

Twitter/X

Primary paths: direct X API or Bird session. Relay supported.

text image video by workflow threading
1

Add channel

Choose `Twitter/X` from Add Channel.

2

Choose method

`X API keys + user tokens`, `Bird session or cookie tokens`, or `Managed relay`.

3

Configure

Direct path needs API key, secret, access token, access token secret. Bird path may use local browser session or explicit cookies.

4

Verify

Resolve handle, permission set, post capability, media support, thread rules.

5

Connected state

Show provider badge `direct / bird / relay`, threading rule, reconnect status.

Create post flow

  • Select `X` in composer.
  • Enter text, optional media, optional first comment equivalent disabled.
  • Long-post behavior: single post if valid, thread if Bird/direct policy allows.
  • Preview numbering if thread split is enabled.

Validation

  • Character budget after numbering.
  • Media-count and upload constraints.
  • Thread chunk limit.
  • Provider fallback decision if direct fails and Bird exists.

LinkedIn

Direct OAuth app for profile or page/company publishing.

text image video page vs member
1

Add channel

Select `LinkedIn`.

2

Enter app creds

Client ID, client secret, refresh token, optional URN/account ID.

3

Resolve owner

Determine whether posting is for a member profile or company page.

4

Verify perms

Check scopes, page ownership, media upload rights.

5

Connected state

Show account label, owner type, media support, reconnect action.

Create post flow

  • Select `LinkedIn` in composer.
  • Choose text/image/video style as supported.
  • Preview as profile or company card.

Validation

  • Owner type determines allowed post variants.
  • Document/article/poll can be later extension.
  • Reject actions if required scopes are missing.

YouTube

video shorts no API-key-only writes

Add channel

Select `YouTube`.

2

Enter OAuth creds

Google client ID, client secret, refresh token, optional channel ID.

Resolve channel

Upload capability, title rules, Shorts-only policy if configured.

5

Connected state

  • Select `YouTube` in composer.
  • Video upload path with title, description, visibility.

  • Thumbnail, title, and length checks.

Pinterest + Reddit

Custom OAuth / app-credential paths. Community-specific rules.

custom rule-heavy

Pinterest flow

  • Add Channel → Pinterest.
  • Enter client ID, client secret, refresh token.
  • Resolve board routing through operator instructions.
  • Composer should ask for destination board before publish.

Reddit flow

  • Add Channel → Reddit.
  • Enter client ID, client secret, refresh token.
  • Resolve subreddit and flair requirements.
  • Composer must validate subreddit rules before schedule/publish.

Parity-Later Platforms

In BrightBean spec, not yet in current `social-poster` connection catalog.

threads bluesky google business mastodon

Doc rule

  • Use same shape: connect → verify → compose variants → validate → publish actions.
  • Add official-doc links once provider contract lands.
  • Do not promise capabilities in UI before explicit capability records exist.

Implementation rule

  • Every platform gets a capability matrix.
  • Composer only exposes format tabs that the account actually supports.
  • Validation happens before approval/schedule/publish.
