Page Flows

Shell → page → nested subflows. this is the menu/page reference for implementation.

Workspace Shell

`Publish`, `Create Idea`, `Social Inbox`, `Replies`, `Notifications`, `Schedules`, `Categories`, dynamic `Channels`, footer actions `Manage Team / Settings / Log out`.

Publish

Workspace → Publish → switch `Calendar / List` → list tabs `Queue / Drafts / Approvals / Sent` → open post → edit / schedule / approve / publish / inspect publish log.

Create Idea

Workspace → Create Idea → `Ideas / Templates / Feeds` → full composer → channels → media → per-channel tweaks → `Save Draft / Submit for Approval / Add to Queue / Schedule / Publish Now`.

Social Inbox

Workspace → Social Inbox → `All / My Queue / Unassigned` → thread feed → open conversation → assign / label / saved reply / SLA handling / reply.

Replies

Keep current `Replies` as dedicated X engine/debug surface until inbox reply parity is complete.

Schedules + Categories

Keep current `Schedules` and `Categories` as first-class automation pages even though they are not BrightBean-primary pages.

Notifications

Global bell or page entry → drawer/history → mark read → open item → deep link into post, approval, inbox, failure, or account issue.

Channels

Sidebar account rows show connected/unhealthy accounts, queue pressure, reconnect state, and Add Channel entry.

Publish nested flows

  • Modes: `Calendar`, `List`.
  • Calendar views: `Month`, later `Week`, `Day`.
  • List tabs: `Queue`, `Drafts`, `Approvals`, `Sent`.
  • Queue flows: `Publishing Queues`, `Queue Detail`, `Add to Queue`, `Prioritize`.
  • Post drill-in: post content, approvals, versions, publish log, platform results.

Create Idea nested flows

  • Landing tabs: `Ideas`, `Templates`, `Feeds`.
  • Idea board: create/edit/move/delete, convert to post.
  • Template gallery: use template, save as template.
  • Feeds: curated sources, add/delete feeds.
  • Composer: channels, caption, media, preview, per-channel overrides.

Settings + portal shells

  • Org Settings: `Profile`, `Preferences`, `General`, `Workspaces`, `Team Members`, `All Calendars`, `Media Library`.
  • Workspace Settings: `General`, `Social Accounts`, `Media Library`, `Approvals`, `Client Portal`.
  • Client Portal: `Home`, `Approvals`, `Published`, `Activity`, optional `Reports` later.

Handoff Notes

Implementation constraints and coding sequence.

Port rule

  • Copy BrightBean IA, menus, tabs, flow order, CTA order.
  • Do not paste Django views, HTMX endpoints, or Alpine runtime code.
  • Rebuild inside Next.js, React, Drizzle, API routes, and server actions.
  • Keep current schedule engine, runtime-vs-DB health, categories, pipeline run truth, and new connections method model.

Current runtime truth

  • `Bird` is the only provider with a true separate runtime publishing path today.
  • Most non-Bird “direct” methods are currently UI/config shapes; runtime still collapses to Late/relay in many cases.
  • Capability records must become explicit before exposing all format tabs in real UI.
  • Validate before approval, schedule, and publish. never after.

Build order

  • Tenancy shell and membership primitives.
  • Workspace shell nav.
  • `Publish` shell.
  • `Create Idea` composer.
  • Workspace settings + social accounts.
  • Approvals + client portal.
  • Inbox + notifications.

What stays top-level

  • `Replies` stays top-level for now.
  • `Schedules` stays top-level.
  • `Categories` stays top-level.
  • `Dashboard` overview is optional, not required by shell parity.

Official-doc rule

  • Use official provider docs first when implementing any platform edge case.
  • Re-check official docs during implementation for unstable provider rules.
  • Treat parity-later platforms as gated until docs + capability mapping are confirmed.
