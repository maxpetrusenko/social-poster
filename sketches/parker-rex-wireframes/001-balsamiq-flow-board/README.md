## Variant: Balsamiq Flow Board

### Design stance
A deliberately rough, Balsamiq-like planning board that makes the pre-implementation state model and Codex change brief visible on one screen.

### Key choices
- Layout: three columns — thread-question inputs, wireframe canvas, Codex iteration brief.
- Typography: hand-drawn system fallback using Comic Sans/Bradley Hand to keep it in wireframe mode.
- Color: warm paper background, black sketch outlines, light blue/yellow accents; no dark mode.
- Interaction: select a thread question, switch workflow tabs, send the bullet brief, toggle an error state.

### Trade-offs
- Strong at: answering Parker’s “mockups ahead of long-horizon tasks” point and Samuel’s annotation/feed-back question.
- Weak at: final visual polish; it intentionally resists looking like production UI.

### Best for
- Early product planning where the team needs to agree on states, affordances, and implementation scope before a long Codex run.
